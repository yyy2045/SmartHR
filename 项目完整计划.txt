一、项目功能与模块划分
1. 系统管理模块
用户认证与权限：HR/面试官/管理员的注册、登录（JWT）、角色权限控制

企业管理：企业信息维护、企业知识库权限

系统配置：LLM API密钥配置、向量数据库连接配置

2. 岗位管理模块
岗位JD的创建、编辑、删除、列表

岗位需求自动标签提取（AI 辅助解析关键技能）

3. 简历管理模块
批量简历上传（PDF/Word解析，文本提取）

简历解析与标准化（AI解析为结构化字段）

简历与岗位JD匹配度计算（RAG+向量相似度）

匹配结果展示：打分、关键匹配点、不匹配风险

4. 智能面试模块（多智能体协作）
面试会话创建：选择岗位、候选人，初始化虚拟面试委员会

实时对话交互：主面试官智能体动态提问，候选人作答（文本输入）

多智能体并行评估：

技能评估智能体：答案技术准确性分析，必要时调用外部检索工具

行为分析智能体：软素质、逻辑性、协作倾向评分

面试状态管理：基于Redis的断点续面、上下文记忆

面试报告生成：交叉验证、加权评分、录用建议

5. 上下文记忆与连续性模块
Redis会话管理：存储对话历史、岗位上下文、HR偏好

面试中断恢复：从Redis恢复完整状态继续面试

HR操作偏好学习：记录筛选偏好并自动适配后续推荐

6. 企业动态知识库模块
文档上传（公司制度、技术规范等，支持PDF/Word/Txt）

文档分块与向量化存入向量数据库

面试过程中检索知识库，辅助生成提问或评估标准

7. 评估报告与历史模块
面试报告查看：结构化报告含各维度得分、总评、录用建议

历史面试记录检索与对比

报告导出（PDF）

8. AI 服务模块（Python 端）
RAG流程：简历-JD匹配、知识库增强生成

多智能体状态图：LangGraph定义面试官与评估智能体协作流程

工具调用：检索工具（向量DB）、事实核验工具

FastAPI接口：/match, /interview/start, /interview/answer, /interview/report等

二、页面原型设计
1. 登录/注册页
表单：邮箱、密码、角色选择

企业注册额外字段：企业名称、行业

2. 工作台首页（HR视图）
快捷入口卡片：发布岗位、上传简历、开始面试、查看报告

最近岗位列表、待面试候选人提醒

偏好摘要：如“最近关注Python岗位”

3. 岗位管理页
表格列表：岗位名称、部门、发布时间、状态

新增/编辑岗位表单：富文本JD编辑，自动生成标签预览

删除确认弹窗

4. 简历管理页
上传区：拖拽批量上传，解析进度条

简历列表：候选人姓名、邮箱、匹配度分数、解析状态

匹配详情弹窗：岗位要求对比、得分雷达图、匹配点高亮

筛选：按匹配度排序，按技能过滤

5. 智能面试页（核心）
左侧：面试对话区，类似聊天界面，显示主面试官问题和候选人回答（模拟输入）

右侧：当前面试状态面板

已提问题列表

实时技能评估简易进度条

行为分析指示灯（持续分析中）

顶部：面试控制栏——开始面试、暂停、结束并生成报告

断点恢复提示：检测到未完成会话时询问是否继续

6. 知识库管理页
文档上传区（支持拖拽）

已上传文档列表：文件名、上传时间、向量化状态

文档内容预览（前200字）

删除与重新向量化操作

7. 面试报告页
候选人基本信息、面试时间

综合评分圆环图、录用建议醒目文字

各维度评分条形图（技术技能、经验匹配、软技能等）

面试问答回顾（折叠式详情）

交叉验证结论描述

导出PDF按钮

8. 系统配置页（管理员）
LLM服务配置：API地址、密钥、模型名

向量数据库连接配置

Redis/MySQL连接状态监控

三、完整开发流程计划
第0阶段：环境与工具准备（1天）
安装并配置：

JDK 17、Maven、Node.js 18+

Python 3.10+、Poetry或pipenv

MySQL 8、Redis 7、向量数据库（如Milvus Lite或Chroma）

IDE（IntelliJ IDEA、VS Code）

创建项目仓库，初始化Java Spring Boot项目（spring-boot-starter-web, security, data-jpa, redis）和Python FastAPI项目

搭建基础docker-compose（MySQL, Redis, 向量DB）

第1阶段：后端基础架构搭建（5天）
Java 后端：

数据库表设计（用户、角色、企业、岗位、简历、面试会话、报告等）

整合Spring Security + JWT实现认证授权

用户与企业管理CRUD API

岗位管理CRUD API

全局异常处理、统一响应体

集成Redis与Spring Cache

Python AI 服务：

FastAPI骨架，健康检查端点

配置LLM客户端（如openai库或langchain适配的多种模型）

连接向量数据库，实现基础向量插入与检索方法

第2阶段：简历匹配与解析功能（6天）
Python端开发：

简历解析微服务：接收PDF/Word文件，提取文本，利用LLM提取结构化字段（姓名、工作经验、技能等）

JD关键信息提取：同样利用LLM提取技能、年限、学历等

向量化：文本分块，调用嵌入模型生成向量存入向量DB

RAG匹配流程实现：根据JD向量检索简历分块，结合LLM生成匹配度评分与理由

对外接口：POST /parse-resume, POST /match等

Java端调用：

简历上传接口，保存文件与解析结果到MySQL

调用Python AI服务获取匹配分数并存储

简历列表与详情查询API

第3阶段：智能面试多智能体系统（8天）
Python端核心：

定义LangGraph状态图：

状态包含：面试历史消息、当前问题、技能评估快照、行为分析快照、最终报告

节点：主面试官（生成问题）、技能评估、行为分析、综合报告生成

条件边：每轮回答后触发评估节点并行，完成后返回主面试官决定继续或结束

实现各智能体提示词模板与工具绑定：

技能评估智能体可调用向量检索工具核验事实

行为分析智能体无需外部工具，纯分析

集成知识库检索：在生成问题或评估时，从企业知识库检索相关片段加入上下文

会话状态存取：所有智能体状态序列化存入Redis（面试ID为键），每次交互时恢复状态

接口设计：

POST /interview/start（传入岗位ID、简历ID）初始化状态，返回第一个问题

POST /interview/answer（传入面试ID、回答文本）触发多智能体处理，返回下一问题或结束信号

GET /interview/report/{id} 返回最终报告

Java端适配：

面试会话管理API（创建会话、提交答案、获取报告）

实现断点恢复逻辑：前端请求面试状态时，Java从Redis读取状态存在与否，返回是否可继续

第4阶段：上下文记忆与连续性实现（3天）
在Redis中设计存储结构：

interview:{sessionId}: hash存储完整状态序列化JSON

hr:{userId}:preferences: 存储HR筛选偏好（如常用关键词）

HR偏好学习：在简历匹配请求中记录检索条件，更新偏好

面试恢复：前端检测到未完成会话可调用GET /interview/status/{id}，若存在则显示“继续面试”按钮

第5阶段：企业知识库模块（3天）
Python端：

文档上传解析（支持PDF、Word、Txt）

文本分块、嵌入、存入向量数据库，带上企业ID元数据

检索接口：根据查询返回最相关片段，支持过滤企业

Java端：

知识库文件管理API（上传、列表、删除）

在面试服务调用时，通过企业ID传递知识库检索需求

第6阶段：前端页面开发（8天）
使用Vue3 + Element Plus（或React + Ant Design）实现所有原型页面：

项目初始化、路由配置、登录态管理

登录/注册页

工作台Dashboard

岗位管理页（集成富文本编辑器）

简历管理页（文件上传、列表、匹配详情弹窗）

智能面试页（聊天组件，状态显示，断点恢复对话框）

知识库管理页（文件上传列表）

面试报告页（图表使用ECharts）

系统配置页（表单）

前后端联调，接口对接

第7阶段：集成测试与调试（5天）
端到端流程测试：注册→发布岗位→上传简历→查看匹配→开始面试→模拟问答→生成报告

多智能体协作一致性验证：检查报告交叉验证逻辑

断点恢复测试：模拟面试中关闭浏览器，重新登录继续

知识库检索准确性测试

性能测试：并发上传简历、同时面试会话压力测试（如有需要）

修复缺陷，优化体验

第8阶段：部署与文档（2天）
编写Docker Compose一键部署（包含MySQL、Redis、向量DB、Java、Python、前端Nginx）

编写README：项目介绍、环境要求、启动步骤、API文档链接

可选的自动化演示脚本
