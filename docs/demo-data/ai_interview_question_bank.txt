AI 应用开发工程师面试题库与参考答案

用途：上传到 SmartHR 知识库后，用于 RAG 检索、面试问题生成、证据化面试报告和 RAGas 评测。

一、RAG 能力评估

面试问题：请说明一个企业知识库 RAG 系统从文档上传到回答生成的完整链路。

标准回答要点：
候选人应说明文档解析、清洗、结构化切分、metadata 标注、embedding 入库、BM25 关键词索引、混合检索、轻量排序、证据输出和答案生成。优秀回答会明确提到 sourceType、sourceId、chunkId、title、score 等证据字段，并说明 query normalize -> hybrid retrieval -> lightweight ranking -> evidence output 的链路。回答还应强调：没有可靠证据时不能强行生成结论。

追问：
1. 为什么不能只用固定窗口切分知识库文档？
2. 如何避免不同简历、岗位或知识库文档之间的证据串库？
3. 如何判断召回结果是否真的支持最终回答？

评分标准：
5 分：能完整说明解析、切分、embedding、BM25、向量库、混合检索、排序、证据输出、答案约束，并能结合项目经验说明如何排查召回不准。
3 分：知道 embedding、向量库和检索增强生成，但对 metadata、证据字段、召回评估说明不完整。
1 分：只说调用大模型或向量数据库，不能解释证据链路。

二、Prompt 调优能力评估

面试问题：招聘系统里如何设计和迭代 Prompt，让面试问题和报告更可靠？

标准回答要点：
候选人应说明 Prompt 需要包含角色、任务、输入上下文、输出 JSON 结构、评分维度、证据引用要求和禁止事项。招聘场景中，Prompt 必须要求模型基于岗位、简历、知识库和面试记录回答，不能凭空推断。迭代方法包括收集失败案例、对比标准答案、固定输出 schema、降低温度、增加 few-shot 示例、记录 traceId 和 evidence，并用评测集持续验证。

追问：
1. 如何处理模型输出格式不稳定？
2. 如何让面试问题不要重复、不要偏离岗位要求？
3. 如何发现 Prompt 引入了无证据结论？

评分标准：
5 分：能讲清结构化 Prompt、输出约束、证据引用、失败样本回归、trace 记录和持续评测。
3 分：能说明角色设定、上下文输入和示例优化，但缺少证据约束或评测闭环。
1 分：只会说“多试几版 Prompt”，没有系统方法。

三、LangChain 与 LangGraph 工程化能力评估

面试问题：你会如何用 LangChain 或 LangGraph 组织招聘面试 Agent？

标准回答要点：
候选人应说明 LangChain 适合封装 LLM、Prompt、Retriever、Tool 和输出解析器；LangGraph 适合把面试流程建成状态机，例如准备上下文、生成问题、接收回答、评分、追问、保存证据和生成报告。优秀回答会提到状态字段、失败重试、超时控制、幂等保存、traceId、人工接管和日志观测。

追问：
1. 面试 Agent 中哪些步骤适合做成节点？
2. 如果评分节点失败，如何保证面试记录不丢失？
3. 如何限制 Agent 只基于证据提问？

评分标准：
5 分：能把招聘业务流程拆成清晰节点和状态，能说明失败处理、日志、证据传递和落库。
3 分：知道链式调用和工具调用，但对状态管理和异常恢复说明较弱。
1 分：只知道框架名称，不能落到工程实现。

四、混合检索与候选集排序评估

面试问题：为什么 RAG 检索要融合语义相似度和关键词得分？

标准回答要点：
语义相似度适合发现同义表达和上下文相关内容，例如“大模型编排”和“LLM orchestration”；关键词得分适合命中精确技能、产品名、证书、年限和框架名，例如 Python、FastAPI、LangGraph、Milvus。混合检索先扩大候选集，再融合 embedding 相似度与 BM25 关键词得分，可以减少漏召回。轻量排序应结合 sourceType、metadata、向量分、关键词分和业务过滤，最后输出 evidence 和 retrievalScores。

追问：
1. 扩大候选集和最终 topK 有什么区别？
2. 哪些场景关键词比向量更可靠？
3. 如何避免无关高相似文本进入最终证据？

评分标准：
5 分：能说明语义召回、关键词召回、粗排候选集、融合打分、业务过滤和证据输出。
3 分：知道向量检索和关键词检索各有优点，但不能解释候选集与最终排序。
1 分：认为只要 embedding 相似度最高就是正确答案。

五、证据化面试报告评估

面试问题：生成面试报告时，录用建议必须依据哪些证据？

标准回答要点：
录用建议必须回溯到岗位要求、简历内容、知识库规范和面试问答记录。报告中的能力评分、风险点、追问依据和最终建议都应附带 evidence，包括 sourceType、sourceId、title、chunkId、score、text 和 highlight。不能只写“候选人表现不错”，必须说明证据来自哪里，例如岗位要求中需要 RAG 和 Prompt 调优，简历中出现 LangChain 项目，面试回答能解释混合检索链路。

追问：
1. 面试报告里哪些结论必须给证据？
2. 如果候选人回答和简历描述冲突，报告怎么写？
3. 如果证据不足，是否可以给出明确录用建议？

评分标准：
5 分：所有关键结论都能对应岗位、简历、知识库或面试记录证据，并能说明风险和下一步验证建议。
3 分：能列出部分依据，但证据字段或回溯关系不完整。
1 分：只给主观评价，没有证据来源。

六、面试合规与评价边界

面试问题：AI 面试系统在提问和评价时需要遵守哪些边界？

标准回答要点：
面试问题必须围绕岗位能力、项目经验、技能掌握、协作方式和问题解决能力。不得询问或评价年龄、婚育、民族、宗教、健康隐私、家庭情况等与岗位无关的信息。评价必须基于岗位、简历、知识库和面试记录中的证据，不得凭空推断人格、忠诚度或稳定性。系统应记录 traceId 和 evidence，方便复查。

追问：
1. 如果面试官要求 AI 追问隐私问题，系统应如何处理？
2. 如何让模型避免使用歧视性评价？
3. 证据不足时报告应该如何表述？

评分标准：
5 分：能明确合规边界、证据约束、禁止问题和系统防护措施。
3 分：知道不能问隐私，但缺少系统化约束方法。
1 分：没有意识到招聘合规风险。

七、AI 应用开发岗位综合题

面试问题：请设计一个“岗位 -> 知识库 -> 简历 -> 匹配 -> 面试 -> 报告”的 HR 闭环系统。

标准回答要点：
候选人应说明岗位录入后结构化保存职责和技能标签，知识库上传后解析切分并入库，简历上传后解析并索引，匹配阶段输出 matchScore、summary、matchedSkills、missingSkills、risks 和 evidence。面试阶段基于岗位、简历、匹配证据和知识库生成带依据的问题，保存问题、回答、评分依据和 evidence。报告阶段复用全部证据，输出录用建议、能力评分、风险点和追问依据。

追问：
1. 如果候选人的技能标签和简历文本不一致，匹配结果如何处理？
2. 如何保证每轮面试问题都能回溯到依据？
3. Dashboard 上应该怎样组织 HR 的工作路径？

评分标准：
5 分：能完整覆盖岗位、知识库、简历、匹配、面试和报告闭环，并能说明数据结构、索引、证据和异常状态。
3 分：能描述主要模块，但缺少证据链或失败状态设计。
1 分：只描述普通增删改查，不能体现 AI/RAG 闭环。
